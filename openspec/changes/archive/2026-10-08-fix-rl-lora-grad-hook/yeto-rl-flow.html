Yeto RL 岛调用流

从本机敲下 yeto launch --training-mode rl 开始，到 head 上的 syncer、岛上的 Miles 训练循环、每轮的 policy sync、最后回收，每一步经过哪个函数。以 2026-09-24 的 yeto-gh4（head 在 Nebius，岛在 Modal 1×H100）为准。

一、三方时序：本机 → head VM → 岛

二、岛内一轮：Miles 循环与 MilesPolicySync 钩子

三、每一步对应的代码

A. 本机：yeto launch

步骤做什么代码
A1解析参数，`--controller head`（默认）走 head 模式yeto/cli.py cmd_launch → cmd_launch_head
A2RL provenance：reward 函数必须是 package.module:func 且能定位；算它的 SHA256；model/data revision 必须是不可变 commit；bundle SHA、Miles/SGLang pin 装进 payloadyeto/launcher.py _prepare_rl_args、_rl_callable；yeto/provenance.py
A3拼 head task：workdir = 整个仓库；setup 用 cargo 编译 syncer/ 成 ~/yeto-syncer；只挂载 fleet 用到的云凭据_make_head_task、launcher.build_syncer_binary、head_cloud_credentials
A4sky.launch 开 head（cpu-d3，eu-north1），再 sky.exec 提交 job：python -m yeto.cli head <payload json>_sky_launch_head、_sky_exec_head
A5写本机 run registry，流式打印 head job 日志；Ctrl-C 只是脱离_record_head_result、_stream_head_logs；之后 yeto logs/status/down

B. head VM：yeto.cli head

步骤做什么代码
B1起 syncer 子进程：~/yeto-syncer --port 29400 --learners N --quorum … --pipeline 1（strict-avg 预设）；只有 checkpoint 存在时才加 --resume（pr10）cmd_head → launcher.LocalSyncer.start、syncer_command、_resume_if_exists
B2syncer 日志转发进 job 日志；tape 写到 ~/yeto-output/yeto-tape.jsonl（可选 W&B）start_log_forwarder、start_tape_forwarder、yeto/wandb_tape.py
B3为每个岛拼 sky task：setup 脚本 = 校验 bundle SHA → clone Miles@MILES_BASE_COMMIT → git fetch bundle MILES_COMMIT → checkout、工作树必须干净 → pip -e ~/miles、SGLang；run 脚本 = ray start → python -m yeto.rl.learner …launcher.run → make_miles_island_task
B4开岛：Modal 走 modal_runner（容器里执行同一份 setup/run）；sky 云走 sky.launchbuild_modal_island_config、modal_runner.py；FleetController
B5监督循环：每 tick _probe = 查 job 状态 + cluster 是否 UP；job SUCCEEDED → DONE；否则进 recovery 重新 launch；strict 失败直接 raiseFleetController.run、_probe、_enter_recovering、_drive_recovery、rl_strict_failure
B6全部 learner 完成 → 拆岛，打印 “run finished; model + checkpoint live on the head”FleetController 收尾 → Modal app stop / sky down

C. 岛：yeto.rl.learner

步骤做什么代码
C1再验一遍：源码树 SHA、model/data revision 不可变、reward SHA 与 head 给的一致learner.main；verify_source_tree_sha256、python_spec_sha256
C2校验 ~/miles：HEAD == MILES_COMMIT、origin == MILES_REPOSITORY、detached、干净yeto/rl/miles.py 的 Miles 检出校验（MILES_COMMIT 处）
C3把 CLI 参数翻成 Miles 的 args：LoRA、GRPO、rollout 规模、external_policy_sync_path = yeto.rl.miles:…、yeto_rl_* 一族、事件 tape 路径 ~/yeto-output/rl-island-<id>.jsonllearner.run_miles
C4进入 Miles：asyncio.run(miles_train(args))~/miles/train.py train

D. Miles 训练循环里的 Yeto 钩子

步骤做什么代码
D1_load_external_policy_sync 按路径实例化 MilesPolicySync(args)（decoupled 预设则是 DecoupledMilesPolicySync）train.py:253；yeto/rl/miles.py MilesPolicySync
D2initialize：导出初始 adapter → _BridgeRuntime → StrictRlBridge.start 向 syncer 发 INIT_PARAMS → 等全局 v0 → _apply_global_policy → wait_for_round 拿许可；start_rollout_id 设为全局版本MilesPolicySync._initialize；yeto/rl/bridge.py StrictRlBridge
D3每轮：rollout_manager.generate（SGLang 采样，调用 reward 函数，按组归一化 reward = 优势）→ actor_model.train（Megatron：反向、DDP hook 把梯度写进 main_grad、optimizer.step 返回 grad_norm）train.py 循环；miles/backends/megatron_utils/actor.py
D4after_local_train：见图二的 6 步；期间 _collective_adapter_tensors 和 apply_trainable_state 都用 _optimizer_masters_as_model_parameters 暴露 fp32 masterMilesPolicySync._after_local_train；miles/backends/megatron_utils/trainable_state.py
D5syncer 侧：收齐 quorum → 合并（strict-avg 等权平均）→ 写 tape：outer step、gnorm（全局 delta 范数）、quorum_ms、sync_ms（只是 merge 耗时）syncer/src/server.rs
D6save（岛 checkpoint 含 rollout metrics）→ update_weights 把新 adapter 发布给 SGLang → 下一轮train.py；MilesPolicySync._rollout_metrics 读回这个 checkpoint
D7最后一轮：finalize → final cut → syncer “training complete after N outer steps” → learner 进程退出 0MilesPolicySync.finalize、StrictRlBridge.finalize

E. 回收

步骤做什么代码
E1head 自己拆岛（Modal app stop；sky 岛 sky down），head job 结束但 head VM 留着（模型和 checkpoint 在上面）FleetController 收尾
E2本机 yeto down <prefix>：按 registry 里记的集群名 sky down head、再 stop 一次 Modal appyeto/cli.py cmd_down、_sky_down_cluster
E3核验：modal app list 为 stopped/0 tasks；nebius compute instance list 无自己前缀手工

四、这次踩到的三处，各在哪一步

  • B1 没合 pr10 时，syncer 一启动就因 --resume 找不到 checkpoint 退出，岛开出来也连不上（gh1）。
  • B4/B5 sky 云上的 RL 岛：run 脚本先 ray stop --force，把 SkyPilot 自带的 Ray（6380）也杀了，sky 把集群标成 INIT，_probe 当失联，无限 relaunch（gh2，第 37 条）。Modal 岛没有 sky 在旁边，所以没事。
  • E2 head 用 sky 开的岛不在本机 registry 里，先拆 head 就留下孤儿 VM（第 36 条）。

D4 的修复：_optimizer_masters_as_model_parameters 不再把 fp32 master 赋给 bf16 Parameter.data（那会重置梯度累加器、丢掉 DDP hook），而是临时替换模块 _parameters 里的条目。gh4 上 train/grad_norm 从恒为 0.0 变成 0.028/0.022/0.022/0.015/0.025/0.027，tape 的 gnorm 从 4e-6 变成 0.0117 起、随 lr 衰减。
