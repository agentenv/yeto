# Spec Delta

## Purpose
让 agentic RL 在生成阶段少等长尾轨迹、少空转 GPU，同时保留确定性模式作为默认和对照基线。

## ADDED Requirements

### Requirement: 确定性模式保持默认且不受影响
权重版本落后上限 SHALL 默认为 0。为 0 时系统 MUST 与本 change 之前的行为一致：样本全部来自当前发布版本，续训切点不携带未完成轨迹，确定性标准样本除契约哈希迁移外逐字节不变。

#### Scenario: 默认配置
- **WHEN** 不设任何新开关启动单岛或多岛运行
- **THEN** 契约中落后上限为 0，任何非当前版本生成的样本仍按现有规则报错

#### Scenario: 标准样本回归
- **WHEN** 用默认配置重新生成标准样本
- **THEN** 只有契约哈希按 hash-migration.md 记录变化，其余字节不变

### Requirement: 多发请求与截止
设置多发数量大于目标条数时，生成阶段 SHALL 在凑够目标条数后截止本轮，未完成轨迹按落后上限处理：上限为 0 时丢弃，并在事件中上报丢弃条数与其已生成 token 数。

#### Scenario: 凑够即截止
- **WHEN** 目标 24 条、多发 48 条、落后上限 0
- **THEN** 第 24 条完成后本轮进入训练，事件记录丢弃条数和丢弃 token 数，训练样本恰为 24 条且全部来自当前版本

### Requirement: 落后上限进契约
落后上限 SHALL 写进契约哈希。多岛中落后上限不同的岛 MUST 被拒绝加入，拒绝只作用于该连接。

#### Scenario: 岛间不一致
- **WHEN** 一个岛落后上限为 1，同步服务的契约为 0
- **THEN** 该岛加入被拒绝并给出原因，其他岛照常运行

### Requirement: 未完成轨迹续跑与版本段记账
落后上限大于 0 时，截止时未完成的轨迹 SHALL 留到下一轮续跑；每个 token MUST 记录生成它的权重版本；样本中最旧版本与当前版本之差 MUST NOT 超过上限，超过的轨迹丢弃并上报。训练 MUST 对跨版本 token 做重要性采样修正，并上报截断比例。

#### Scenario: 跨一个版本续跑
- **WHEN** 落后上限 1，一条轨迹前半由版本 v、后半由 v+1 生成
- **THEN** 该样本进入 v+1 这一轮训练，token 级版本记录完整，修正截断比例出现在指标中

#### Scenario: 超过上限
- **WHEN** 一条轨迹跨越 2 个版本而上限为 1
- **THEN** 该轨迹被丢弃并计入丢弃指标，不进入训练

### Requirement: 续训切点携带未完成轨迹
落后上限大于 0 时，续训切点 SHALL 保存未完成轨迹及其版本段与（agentic 时）可恢复的会话状态；恢复后 MUST 按同样规则续跑或丢弃，且不得重复使用同一题号的已完成样本。

#### Scenario: 中断后恢复
- **WHEN** 有 5 条未完成轨迹时运行被中断，再从切点恢复
- **THEN** 这 5 条要么按上限续跑、要么被丢弃并上报，已训练过的样本不重复出现

### Requirement: agentic 轨迹只在回合之间中止
agentic 多轮轨迹 MUST 只在两个模型回合之间被中止挂起，MUST NOT 在工具执行过程中中止；挂起期间沙箱保持存活或可从快照恢复，存活时间上限可配，超时即丢弃该轨迹。

#### Scenario: 截止时工具正在执行
- **WHEN** 截止到来时一条轨迹的工具调用尚未返回
- **THEN** 等该工具返回、写入对话后再挂起该轨迹，沙箱状态与对话记录一致

#### Scenario: 沙箱存活超时
- **WHEN** 挂起轨迹的沙箱超过存活上限仍未被续跑
- **THEN** 轨迹被丢弃、沙箱被释放，丢弃原因被上报

### Requirement: 两种训练后端行为一致
Miles 与 verl 适配层 SHALL 都从同一个落后上限开关推导各自框架的配置；某后端尚未支持某阶段时 MUST 在启动前报错说明，MUST NOT 静默按 0 运行或忽略开关。两后端的丢弃、版本段与利用率指标 MUST 使用同一套事件字段。

#### Scenario: 后端暂不支持
- **WHEN** 落后上限 1 且所选后端尚未实现该阶段
- **THEN** launcher 在起机器前报错，指出该后端支持到哪个阶段

#### Scenario: 指标字段一致
- **WHEN** 用 Miles 和 verl 各跑一轮同配置
- **THEN** 两者事件流中丢弃条数、版本段、三段耗时字段名与含义相同

### Requirement: 利用率指标
每轮 SHALL 上报：每条轨迹起止时间；每回合模型生成、工具执行、判分三段耗时；沙箱冷启动耗时；推理引擎 KV 占用与排队峰值；截止时丢弃/挂起条数和 token 数；跨版本 token 比例。

#### Scenario: 指标落盘
- **WHEN** 任意 agentic 运行跑完一轮
- **THEN** 事件流中可拆出该轮生成段三段耗时之和与生成段总时长的对应关系
