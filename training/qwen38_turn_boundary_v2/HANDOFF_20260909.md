## What changed

Continuing Codex assistant announcements and tool calls are grouped before Qwen
rendering. The model now receives one assistant header and one true-turn end
token for that continuation. Explicit source-turn, final-channel and role
boundaries remain intact. No original action is reordered.

For masked-CoT, the chosen policy uses the ordinary native assistant template.
A CoT that cannot remain at its original gap is individually omitted. Its trace,
other compatible CoTs and visible assistant targets remain eligible. Even a
trace with no remaining CoT is retained. Original generations and receipts are
preserved; no regeneration or additional semantic approval is implied.

Both corrected runs use the original base and a fresh optimizer. The old
baseline checkpoint424 and masked checkpoint24 remain preserved. A preliminary
corrected masked run was stopped during startup, before any update, when the
user chose individual CoT omission instead of whole-trace exclusion. Its
artifacts remain preserved. The experimental inline-reasoning customization
was canceled and is not part of this branch.

## Qualified data

The no-CoT baseline uses 16,389 rows: 16,246 training and 143 held out. Its frozen
source selection contained 16,683 rows; 209 source-order failures and 85
identical retained token/label arrays were excluded. All 2,346 selected replay
sources remain. Full qualification checked every row and mask, exact shard and
index hashes, original session splits, and zero train/validation group overlap.

The native-gap masked dataset uses 14,979 rows: 14,853 training and 126 held out.
It accounts for all 31,504 frozen generations: 25,344 retained, 828 individually
omitted, and 5,332 on independently excluded sources. All 25,344 retained CoTs
also survive the 262,144-token cutoff. The 1,513 whole-source exclusions are
separate from CoT omission: 1,148 unsupported text-after-tool sequences, 205
other unsupported trace formats, four unsupported message formats and 156
duplicates. Both datasets retain the same selected 2,346 replay sources.

These counts describe formatting and provenance checks. The generated-CoT arm
is still experimental: generation was lookahead-conditioned, and these checks
do not establish that every candidate is free of future-information leakage.

## Training and measurements

The plan remains one shuffled epoch, learning rate `1e-5`, full text-parameter
SFT, and the first 262,144 tokens of each trace. Both use eight H200s on one
host, CP8/FSDP2, fused CE, whole-block activation checkpointing, disabled
prefetch and expandable allocations. Original visible assistant/tool content
and true end tokens train; headers, observations and CoT have zero loss.
Labels are shifted exactly once by the dataset before context parallelism.

The no-CoT baseline has 2,031 optimizer updates. The masked arm has 1,857.
Full checkpoints are saved after update1, then every five updates, with recent
checkpoint retention and exact model/optimizer/loader/RNG resume guards.

The first small quality evaluation uses the checkpoint after 25 completed
updates, followed by 50 and 100. **Training does not stop at those milestones.**
The finite CPU supervisor preserves model snapshots and exports them separately
from the trainer. The fixed 16-task suite measures actual tool action, task
success, premature stops and infrastructure failures under native xhigh
inference. Compare supervised-token budgets as well as update counts. It is not
the full 89-task Terminal-Bench evaluation.

## Validation and remaining evidence

The isolated code/dependency copy passed 215 CPU tests before the final
documentation additions. Tests cover native rendering, boundaries, masks,
262k cutoffs, single label shifting, generation/omission receipt binding,
zero-CoT trace retention, full export/index integration and quality tooling.
The launch helpers additionally exercise the actual pinned training image,
Torch loader/collator and installed fused-loss shift behavior.

Earlier no-CoT step299 scored 5/89 with the corrected inference template. The
source-turn defect is a confirmed training-data problem, but improved benchmark
performance after this correction is not yet measured. A decreasing training
loss alone does not establish recovery. Full numerical forward parity between
training and serving implementations also remains unmeasured.
