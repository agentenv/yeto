# EXP2.22: Online Scalar Action Probing

## Question

Does the disjoint-anchor scalar selector improve an actual asynchronous
training trajectory when it commits its selected preview, compared with a
matched shadow run that performs the same probes but always commits the
multiplier-1 preview?

Candidate AUROC and one-step replay are not success criteria here. The online
gate is lower held-out loss for `probe_lr_v1` than `probe_lr_shadow` under the
same learner, delay, anchor, probe, and outer-optimizer configuration.

## Two-Step Protocol Smoke

Shadow and active were run separately with identical shuffle seed 223 and
training seed 223. This training RNG seed is fresh relative to the offline
seed-223 capture, which used training seed 223223.

| Arm | Outer steps | Selected actions | Committed actions | Fallbacks | Mean probe latency | Eval loss |
|---|---:|---|---|---:|---:|---:|
| `probe_lr_shadow` | 2 | A4, A4 | A0, A0 | 0 | 5.99 s | 1.527360 |
| `probe_lr_v1` | 2 | A4, A4 | A4, A4 | 0 | 6.58 s | **1.504759** |

The active smoke improves held-out loss by `0.022601` after two outer steps.
This is an execution and direction check, not a sufficient training result.

Both tapes contain exactly two complete four-responder commits. Every
responder reports exactly 64 microsteps and 8,192 tokens. Every request has a
nonzero probe latency and a 64-hex request digest. Shadow commits multiplier
1.0 while active commits the exact retained multiplier-1.5 preview.

## Twenty-Four-Step Development Run

Both arms were launched by one comparison driver, so they share the exact
materialized training/eval split and evaluation path.

| Metric | Shadow | Active |
|---|---:|---:|
| Outer steps | 24 | 24 |
| Eval loss | 1.374886 | **1.373990** |
| Wall time | 549.3 s | 531.2 s |
| Non-A0 action rate | 0.500 | 0.292 |
| Mean probe latency | 5.980 s | 6.133 s |
| Probe latency p95 | 6.789 s | 6.840 s |
| Full-quorum commits | 24/24 | 24/24 |
| Valid request digests | 24/24 | 24/24 |
| Transport/config fallbacks | 0 | 0 |
| Final local steps, total | 2,006 | 1,908 |
| Final raw tokens, total | 256,768 | 244,224 |

Active improves held-out loss by `0.000896`. This is the first nontrivial
online run in the project where an online-executable adaptive policy has lower
measured loss than a matched shadow comparator after the policy's actions have
propagated through learner training.

The selected multiplier distributions are:

| Multiplier | Shadow recommendations | Active commits |
|---:|---:|---:|
| 0.75 | 1 | 0 |
| 1.00 | 12 | 17 |
| 1.125 | 1 | 0 |
| 1.25 | 0 | 2 |
| 1.50 | 10 | 5 |

This difference is expected and is consistent with closed-loop state
dependence rather than a parity failure. Shadow keeps the multiplier-1
trajectory and still recommends multiplier 1.5 ten times. Active commits
larger early steps, moves to a different state, and then abstains sooner: five
1.5 commits, two 1.25 commits, and multiplier 1.0 for the remaining 17 groups.

Because learners continue local optimization while probing is in flight, the
submitted equal 64-step windows do not force equal total learner work. Shadow
finished at per-learner local steps `565/519/457/465`; active finished at
`492/499/440/477`. Active therefore used `12,544` fewer raw tokens and still
had lower measured loss. That is favorable operationally, but the active vs
shadow result is an arm-level outcome and is not attributable solely to the
selected commit tensors.

All A0 selections have the semantic reason `no_action_passed`; none is a
timeout, protocol, configuration, or sidecar failure.

## Fixed-Scalar Control

A probe-overhead/cadence-matched fixed-1.5 control is run as
`probe_lr_shadow` with base outer LR `0.42 = 0.28 x 1.5`. It uses the same
five-action probe code path and pays the same sidecar delay, but always commits
A0, which is the fixed 0.42 step. Its probed effective LR grid is centered on
0.42 rather than 0.28, so it is not an identical-candidate probe. Selector
output is irrelevant to the committed fixed control. It uses the same 24-step
seed-223 materialized split as the development pair.

| Policy | Effective outer LR | Eval loss | Difference vs active |
|---|---:|---:|---:|
| adaptive `probe_lr_v1` | selected per group | **1.373990** | 0 |
| matched shadow x1 | 0.28 | 1.374886 | +0.000896 |
| matched fixed x1.5 | 0.42 | 1.377450 | +0.003460 |

The adaptive policy beats both controls. Fixed x1.5 is also `0.002564` worse
than x1 at this horizon, ruling out the specific strategy of always using
multiplier 1.5; other fixed LRs and schedules were not tested online. The fixed
control completed 24/24 full-quorum commits, emitted 24 auditable decision
records, and had zero transport/config fallbacks.

The active and fixed-1.5 runs have closely matched realized work: active ends
at 1,908 total local steps / 244,224 raw tokens, while fixed-1.5 ends at 1,915
steps / 245,120 raw tokens. Their `0.003460` loss difference is therefore not
explained by a meaningful total-work advantage for active.

## Audit Findings

The smoke used explicit production-faithful flags, but a code audit identified
hardening work required before untouched confirmation:

1. Bind selector thresholds into the sidecar configuration digest.
2. Make online scalar tie-breaking exactly match offline replay.
3. Make the harness fail malformed or all-transport-fallback probe runs and
   emit a compact action-probe run summary.
4. Continue checking the actual materialized train/eval files against the
   anchor manifest, not only the manifest's historical exclusions.
5. Preserve detailed decision evidence needed to audit panel statistics.

Items 1-3 and 5 were implemented at commit `48f8fcd`:

```text
selector thresholds are included in probe_config_sha256;
scalar ties match the offline multiplier order exactly;
the harness validates real responder objects and every probe tape record;
each arm writes action_probe_run_summary.json;
each run writes command.sh, git_commit.txt, and git_diff.patch;
each successful sidecar response logs one ACTION_PROBE_DECISION JSON record.
```

Non-tied selections are unchanged; exact scalar ties now intentionally follow
the offline multiplier order. Item 4 was performed manually before seed 251
and was automated in `d6db744` for subsequent runs.

The 24-step run remains interpretable because its explicit CLI, readiness
record, complete tape, and canonical overlap check are preserved. Untouched
confirmation uses the hardened commit.

## Current Decision

The production shadow and active paths execute correctly. On the single
seed-223, 24-step development pair, active has lower measured 64-row eval loss
by `0.000896` (`0.065%`). Its action distributions are consistent with
closed-loop state dependence, and it beats the cadence-matched fixed-1.5
control by `0.003460`. This passes the directional point-estimate development
gate.

Fresh-seed C1 does not pass its primary directional loss gate, so the
predeclared C2 run is not triggered. The policy remains a positive 24-step
development result with mixed 80-step endpoint evidence. A post-hoc
matched-work diagnostic is in progress to separate commit quality from the
realized learner-work difference; it cannot retroactively convert C1 into a
confirmation pass.
