# EXP2.18: Controlled Qwen3.5-9B Fragment-LR Online Validation

## Question

Does the soft fragment-specific outer-learning-rate profile found by offline
replay improve a real asynchronous Qwen3.5-9B training trajectory when it is
compared against a tuned fixed-learning-rate baseline under controlled random
seeds?

This experiment is deliberately narrower than the earlier ProbeCommit work.
It does not claim that a current-state probe can select an action online. It
tests whether a static fragment-aware outer-optimizer profile survives
long-horizon training after the fixed outer learning rate is tuned.

## Why This Control Was Necessary

Earlier Qwen online comparisons had two serious interpretation problems.

First, the original outer learning rate of `0.35` was not a strong baseline.
Production-parity one-step replay over seeds 59 and 71 found that applying half
of that step, equivalent to a fixed outer learning rate of `0.175`, improved
mean one-step utility by `0.002321`. The gain was positive on both seeds and
had bootstrap `P(gain > 0) = 1.000`.

Second, the first online fragment-profile runs did not explicitly seed learner
randomness. LoRA initialization, preloaded-data shuffling, and delay jitter
could therefore differ between arms. Those runs remain useful diagnostics,
but they cannot establish a policy win.

Commit `26a5787` added explicit learner and harness training seeds. The runs in
this document are the first online comparisons where both arms start from the
same syncer state and produce identical first-window candidate tensors.

## Setup

| Item | Value |
|---|---|
| Model | `qwen35-9b` |
| Source model | Qwen3.5-9B through the repository model resolver |
| Dataset | `trl-lib/Capybara` |
| Instance | AWS `p4d.24xlarge`, 8x A100-SXM4 40GB |
| Learners | 4 logical learners per arm, one GPU per learner |
| Arms in parallel | fixed baseline on GPUs 0-3; soft profile on GPUs 4-7 |
| Token budget | 700,000 tokens per arm |
| Local steps | 1,368 per learner |
| Sequence length | 128 |
| LoRA rank / alpha | 2 / 4 |
| Inner learning rate | 0.001 |
| Fragments | 4, deterministic `binpack` layout |
| Fixed window | 8,192 tokens / 64 microsteps |
| Stress | freeze delta before post-snapshot delays of 0/800/1600/2400 ms |
| Delay jitter | 50 ms |
| Merge | HeLoCo correction, outer momentum 0.9 |
| Fixed baseline | outer LR `0.175` for every fragment |
| Soft profile | `[0.21875, 0.175, 0.13125, 0.1575]` |

The soft profile is `[1.25, 1.00, 0.75, 0.90]` times the tuned fixed LR. It
was selected from offline replay over seeds 59, 71, and 83 before the
controlled online seeds in this document were run.

## Evaluation Data

The training harness materializes at most 5,064 source rows and uses 5,000 for
training plus 64 for its internal evaluation split. The external holdout uses
source indices beginning at 6,000, so it is disjoint from every controlled
training arm by construction.

Two external holdouts are used:

```text
holdout A: 256 rows beginning at source index 6000
holdout B: 256 rows beginning at source index 7000
```

The second holdout was added after the first controlled result, before reading
the second controlled seed result.

## Reproducibility Checks

For each controlled seed, the two arms use the same:

```text
Capybara shuffle seed
learner training seed
initial syncer checkpoint
learner count and GPU topology
post-snapshot delay pattern
token budget
```

The SHA-256 hash of `state_before_step_00000001.ckpt` must match between arms.
The four first-window candidate tensors, one per learner, must also match
exactly. This verifies that the policies begin from the same model and see the
same first local optimization window before their outer updates diverge.

This does not make the complete asynchronous schedules identical. A fixed
window guarantees 64 local steps per response, but a broadcast resets that
fragment's window. Once the policies produce different broadcasts, later
response boundaries and data segments can diverge. Across the original runs,
only 10.9% of seed-101 and 17.3% of seed-113 candidate boundaries matched
exactly after grouping comparable records.

## Result

### Controlled Seed 101

```text

training seed: 424242
initial syncer-state hash:
  83737d65ae93685e62e36883237d4ad97c284c19914eb4263e024bfb2b8cbd2a
```

All four step-1 candidate files matched exactly between arms.

| Evaluation | Fixed LR 0.175 | Soft fragment LR | Soft minus fixed |

### Controlled Aggregate

Define gain as `fixed loss - soft loss`, so positive values favor the soft
profile.

| Evaluation | Seed 101 gain | Seed 113 gain | Mean gain | Seeds positive |
|---|---:|---:|---:|---:|
| Internal eval | +0.0101 | -0.0445 | -0.0172 | 1/2 |
| External holdout A | +0.006355 | -0.046817 | -0.020231 | 1/2 |
| External holdout B | +0.006543 | -0.049219 | -0.021338 | 1/2 |

The original endpoint profile therefore fails the controlled replication
gate, but the unequal outer-step count means the magnitude cannot be
attributed entirely to the fragment LR profile.

## Scheduler Confound

The original harness gave the syncer a generous round ceiling, waited for the
learners to finish, and then terminated the syncer. As learners disconnected,
the syncer reduced its effective quorum to the number still connected. This
created partial tail commits and, in some arms, an additional four-fragment
cycle.

| Run | Outer steps | Full 4-responder groups | Partial groups |
|---|---:|---:|---:|
| Seed 101 fixed | 80 | 68 | 12 |
| Seed 101 soft | 80 | 68 | 12 |
| Seed 113 fixed | 80 | 64 | 16 |
| Seed 113 soft | 84 | 66 | 18 |

Seed 113 soft had 12 one-responder groups and received an additional complete
cycle from learner 3. To isolate that tail, I exported the soft checkpoint
immediately after step 80 and evaluated it against the fixed step-80 endpoint.

| Seed 113 evaluation | Fixed step 80 | Soft step 80 | Soft minus fixed |
|---|---:|---:|---:|
| External holdout A | 1.474150 | 1.482843 | +0.008693 |
| External holdout B | 1.479737 | 1.490636 | +0.010899 |

The profile still loses at the common outer step, but the extra cycle explains
about 78-81% of the original endpoint regression.

## Average-LR Control

Seed 127 compared the profile against a fixed LR equal to its arithmetic mean,
`0.170625`. The first syncer state and all four first-window candidates again
matched exactly.

The same endpoint problem recurred: the fixed arm stopped after 80 outer
steps, while the soft arm stopped after 84.

| Seed 127 evaluation | Fixed 0.170625, step 80 | Soft final, step 84 | Soft step 80 |
|---|---:|---:|---:|
| Internal eval | 1.4732 | 1.5741 | n/a |
| External holdout A | 1.456952 | 1.558999 | 1.517707 |
| External holdout B | 1.461449 | 1.559634 | 1.520271 |

Even at the common step 80, the soft profile is substantially worse on seed
127. The lower mean LR therefore does not explain or rescue the profile.

|---:|---|---:|---:|---:|---:|
| 101 | fixed | 1.329205 | 1.343440 | 1.356578 | 1.400731 |

The sign changes during each trajectory. There is no stable early-versus-late

## Schedule-Locked Seed 113

Commit `7ae4281` added a controlled experiment mode with:

```text
exactly 80 outer steps
strict configured quorum of 4
20 commits per fragment
no timeout or disconnect-driven partial commits
learner step ceiling above the amount needed to finish the outer schedule
post-run validation of tape length and responder count
```

The schedule-locked rerun compared fixed LR `0.170625` against the soft
profile on seed 113. Initial state and all four first-window candidates matched
the hashes reported above. Both event tapes contained exactly 80 groups, all
80 groups had four responders, and every fragment committed exactly 20 times.

| Evaluation | Fixed 0.170625 | Soft profile | Soft minus fixed |
|---|---:|---:|---:|
| Internal 64-row eval | 1.4269 | 1.4262 | -0.0007 |
| External holdout A | 1.428050 | 1.427085 | -0.000965 |
| External holdout B | 1.434402 | 1.433149 | -0.001253 |
| Wall time | 1,467 s | 1,515 s | +48 s |

Once outer-step count and quorum are controlled, the large seed-113 failure
disappears. The soft profile is slightly better on all three evaluations, but
the improvement is only about `0.001`, well below the `0.005` practical gate.
This is a near-tie, not a policy win.

## Interpretation

The experiment separates three claims that should not be conflated:

1. The original fixed outer LR `0.35` was under-tuned. Reducing it mattered
   more than the robust or probe-based policies tested earlier.
2. Before the schedule lock, the static profile beat fixed LR `0.175` on one
   seed and lost badly on others. Under the strict schedule-locked comparison
   against its fixed mean LR `0.170625`, it improves by only about `0.001`.
3. This does not validate candidate-level ProbeCommit, current-state action
   selection, or one-step oracle utility as a long-horizon objective.

The third point is important. The aggressive fragment profile looked positive
in one-step replay on the failed seed-83 trajectory even though its final model
was materially worse. One-step utility is therefore a useful diagnostic but
not a sufficient policy-selection objective.

## Decision

Do not treat the soft fragment profile as a working policy. The
schedule-locked result shows that most of the apparent failures came from
unequal tail commits, but the remaining benefit is too small to justify a
fragment-ID-specific rule. The strongest actionable result is instead that
outer optimizer dynamics and commit scheduling dominate the elaborate
candidate-selection policies tested so far.

## Known Limitations

- The profile is static and architecture/layout-specific, not an adaptive
  statistical commit protocol.
- Four `binpack` fragments do not map cleanly to semantic layer groups. In
  this Qwen LoRA layout, all four fragments contain 124 tensors, span all 32
  transformer layers, have 1,352,448 trainable values, and use RDA. No
  embedding or output-head tensor is trainable, so there is no AVG fragment.
- The profile mean is `0.170625`, 2.5% below the fixed `0.175` baseline. The
  completed strict fixed-`0.170625` control leaves only about `0.001` of
  apparent fragment-specific benefit.
- The current budget is 700k tokens with LoRA rank 2. This is an online
  trajectory test, not a full pretraining-scale result.
- External evaluation is Capybara SFT loss, not broad downstream capability.
- The original endpoint runs did not lock outer-step count or configured
  quorum through learner shutdown. Their tail comparisons are diagnostic, not
  clean causal estimates.

## Exact Commands

The controlled fixed arm has this command shape:

```bash
python scripts/compare_diloco.py \
  --model qwen35-9b \
  --data trl-lib/Capybara \
  --settings m4 \
  --outer-lr FIXED_OUTER_LR \
  --token-budget 700000 \
  --seq-len 128 \
  --micro-batch-size 1 \
  --inner-lr 0.001 \
  --lora-r 2 \
  --lora-alpha 4 \
  --eval-rows 64 \
  --max-rows 5000 \
  --shuffle-rows-seed SEED \
  --training-seed TRAINING_SEED \
  --device cuda \
  --learner-gpus 1 \
  --gpu-offset 0 \
  --baseline-loss 0.0 \
  --fixed-window-tokens 8192 \
  --fixed-window-microsteps 64 \
  --pad-to-fixed-window-tokens \
  --freeze-delta-before-delay \
  --learner-push-delay-ms 0,800,1600,2400 \
  --learner-delay-jitter-ms 50 \
  --syncer-total-steps 80 \
  --learner-max-steps 1600 \
  --strict-quorum \
  --syncer-probe-capture \
  --syncer-probe-capture-every 1 \
  --work-dir RUN_DIR/work \
  --report-dir RUN_DIR/report
```

The original tuned fixed baseline uses `FIXED_OUTER_LR=0.175`. The strict
mean-LR control reported above uses `FIXED_OUTER_LR=0.170625`.

The soft arm adds:

```bash
--outer-lr-by-fragment 0.21875,0.175,0.13125,0.1575
```

and uses `--gpu-offset 4` when both arms run concurrently.
