# EXP2.24: Synchronous Nesterov Decomposition

## Question

EXP2.23 showed vanilla DiLoCo's outer Nesterov (mu=0.9, LR 0.175) losing to
memoryless SGD-0.28 by `0.0594` under a zero-delay schedule. That comparison
confounds three things: the momentum memory itself, the momentum magnitude,
and the effective step scale (the mu=0.9 arm has 6.25x SGD-0.28's
steady-state gain and ran 1.4x larger realized steps). Which one causes the
damage?

## Setup

Four new arms complete a six-point grid with the two EXP2.23 sync arms.
Everything else matches EXP2.23 exactly: Qwen3.5-9B LoRA rank 2, Capybara,
m4 strict quorum, 80 outer groups, zero-delay schedule, seed 223 / 223223,
700k tokens, delta correction none.

```text
provider: Verda spot, FIN-03, 1x RTX PRO 6000 Blackwell 96GB
         (confidential-compute variant; all four learners packed on the
         one GPU via --gpu-slots 1)
image: ubuntu-24.04-cuda-12.8-open
python 3.12, torch 2.8.0 cu128 (Blackwell requires cu128; the A100 runs
         used torch 2.5.1 cu121 — see Limitations)
code commit: 46ed83c
```

| Arm | mu | outer LR | Rationale |
|---|--:|--:|---|
| `sync-sgd-lr175` | 0 | 0.175 | completes fixed-LR momentum sweep {0, 0.5, 0.9} |
| `sync-mu05-lr175` | 0.5 | 0.175 | best async Nesterov corner under sync |
| `sync-mu09-lr0028` | 0.9 | 0.028 | DC gain matched to SGD-0.28: 0.028/(1-0.9)=0.28 |
| `sync-mu09-lr0125` | 0.9 | 0.125 | realized-norm match target 2.87 from EXP2.23 tapes |

All four arms completed 80/80 strict full-quorum groups, 20 commits per
fragment.

## Interpretation

1. **Fixed-LR momentum sweep is monotonic.** At LR 0.175, going mu
   0 -> 0.5 -> 0.9 gives 1.3578 -> 1.3614 -> 1.4193. But momentum also
   inflates realized scale (1.81 -> 2.88 -> 4.02), so this alone does not
   separate memory from scale.

2. **Scale alone does not explain the damage.** Within same-env memoryless
   SGD, a 58% realized-norm change (1.81 -> 2.87) moves loss by only
   `+0.002`. Yet at approximately matched realized norm (2.87-3.15),
   mu=0.9 (1.3982) is `~0.037-0.040` worse than mu=0 (1.3599) and mu=0.5
   (1.3614). The 9.6% norm overshoot cannot account for that: the memory
   rotation itself is harmful at production step scale. The tape shows why:
   mu=0.9 steps run at cosine ~0.77 to the current merged update with
   history/current ~0.78, while mu=0.5 stays at cosine 0.98.

3. **Momentum is harmless when the steps are small.** DC-matched mu=0.9 at
   LR 0.028 (realized norm 0.94) lands at 1.3580 — tied with the best. Its
   direction is equally rotated (cosine 0.74), but at one-third the step
   scale the rotated component is too small to hurt. So the damage model is
   approximately (memory rotation) x (step scale), not either factor alone.

4. **The LR effect for memoryless SGD is a plateau.** 0.175 vs 0.28 differ
   by `0.002` (0.175 marginally better), inside the practical-tie region.
   The tuned SGD-0.28 policy is not sharply LR-sensitive under sync.

Answer to the headline question: it is not the Nesterov formulation per se,
and not the nominal LR — it is momentum's directional memory interacting
with realized step scale. mu=0.9 either runs small (and is pointless) or
runs at working scale (and its history-rotated steps cost ~0.04 loss at 80
groups). This matches and sharpens the EXP2.19 async conclusion; EXP2.23/24
show none of it requires asynchrony.

## Limitations

1. Single seed (223), sync schedule only, 80 groups, one model/data config.
2. The four new arms ran on torch 2.8.0/cu128 (Blackwell); the two EXP2.23
   reference arms on torch 2.5.1/cu121 (A100). All decisive matched-scale
   comparisons (rows 1, 2, 4, 5 of the grid) are same-environment; only
   comparisons against the two EXP2.23 rows cross environments, where the
   sgd-lr175-vs-sgd028 ordering (`0.002`) is within cross-env noise.
3. All four learners shared one 96GB GPU (`--gpu-slots 1`), serializing
   learner steps. Under the zero-delay strict schedule the trajectory is
   schedule-driven, but realized learner overshoot differs from the
   4-GPU EXP2.23 runs.
4. The norm-matched arm overshot its realized-norm target by 9.6%.
5. mu=0.9/LR 0.028 matches DC gain but not the transient: its first-step
   effective gain is 0.0532 vs SGD-0.28's 0.28.

## Operational Notes

The node was Verda's confidential-compute RTX PRO 6000 variant
(`1RTXPRO6000.30V.CC`, $0.67/h spot). Quirks worth recording: it accepts
only certain images (`ubuntu-24.04-cuda-12.8-open` works; the 22.04 CUDA
12.4 image is rejected); the GPU boots in a locked state until
`nvidia-smi conf-compute -srs 1` sets the CC ready state; Ubuntu 24.04
requires a venv (PEP-668); apt has no `awscli` (pip install instead);
Blackwell needs torch cu128 wheels. Total cost of the four arms was about
$2 at 2,150-2,330 s per arm.
