# EXP2.13: Conservative Safety-First Offline Search

## Question

Can a conservative action-probe selector fix the remaining failure mode by using anchor evidence only as a high-confidence veto or shrink rule, while keeping selected mass high?

This test is offline-only. It reuses the EXP2.9 replay artifacts and does not start online training.

## Setup

Input records:

```text
experiment-results/EXP2/probecommit-offline/exp2_9_action_probe/seed53/action_probe_replay.jsonl
experiment-results/EXP2/probecommit-offline/exp2_9_action_probe/seed67/action_probe_replay.jsonl
experiment-results/EXP2/probecommit-offline/exp2_9_action_probe/seed79/action_probe_replay.jsonl
```

Output artifacts:

```text
experiment-results/EXP2/probecommit-offline/exp2_13_conservative/conservative_search.json
experiment-results/EXP2/probecommit-offline/exp2_13_conservative/conservative_search.md
```

Script:

```text
scripts/search_conservative_action_probe.py
```

The search uses held-out-seed evaluation:

```text
train seeds 67,79 -> test seed 53
train seeds 53,79 -> test seed 67
train seeds 53,67 -> test seed 79
```

Oracle utility is used only to score train/test policies, never to select a per-group action.

## Policy Family

The search tried four conservative variants:

```text
high_conf_gain
safety_veto
shrink_veto
risk_lcb
```

The grid covered:

```text
lcb_k: 0, 0.5, 1, 2
margin: 0, 0.00025, 0.0005, 0.001, 0.002
minimum selected mass: 0.5, 0.67, 0.8, 0.9, 1.0
minimum anchor score: -0.002, -0.001, 0, 0.0005
require non-strict-negative anchor action: true/false
fallback: token_weighted or anchor_shrink
```

The search objective is safety-first:

```text
reward negative-rate drop
reward strict-negative-rate drop
weakly reward mean utility gain and oracle-headroom capture
penalize selected mass below 0.85
```

## Interpretation

The conservative search fixed selected mass but did not fix policy quality.

The important result is seed 67 again:

```text
gain = -0.0000979
negative drop = -0.076
headroom captured = -1.081
```

This means the remaining blocker is not just that previous policies dropped too much mass. Even when the policy is forced to stay conservative and high-mass, the anchor signal still does not choose safe improvements reliably across seeds.

The current offline evidence now says:

```text
bad fragments exist,
bad mass can hurt token-weighted merge,
oracle deployable actions have headroom,
small anchor/action-probe policies do not reliably recover that headroom,
conservative high-mass gating does not solve the safety problem.
```

## Decision

Do not start online ProbeCommit from this policy family.

The safety-first selector did not meet the online gate:

```text
mean gain too small,
negative-rate drop too small,
strict-negative drop too small,
headroom capture negative on average,
seed 67 remains a blocker.
```

## Next Step

The only worthwhile continuation is to collect denser and harder measurements, not to run online policy.

Recommended next experiment:

```text
Qwen3.5-9B or Gemma4,
50+ complete groups per seed,
at least 3 seeds,
more anchor batches or repeated anchor splits,
explicit measurement of anchor/oracle action-rank agreement.
```

If that still shows weak action-rank agreement, the policy direction should pivot to a diagnostic/benchmark result rather than an online training claim.
