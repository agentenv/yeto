# EXP2.19: Schedule-Locked Outer-Momentum Policy

## Question

Can a lower-memory outer optimizer improve long-horizon asynchronous Qwen3.5-9B
training more reliably than candidate selection or static fragment-ID learning
rates?

EXP2.18 established two important facts:

1. The original endpoint comparisons were contaminated by disconnect-driven
   partial tail commits and unequal outer-step counts.
2. Once every arm is locked to the same 80 full-quorum outer steps, the static
   fragment profile is only about `0.001` better than its fixed mean-LR control.

The next hypothesis is therefore about trajectory-level optimizer memory, not
which candidate should be accepted.

## Motivation

The tuned baseline uses Nesterov momentum `0.9` for every RDA fragment. A
geometry audit over controlled seed-101 and seed-113 captures found that, after
momentum builds up:

```text
history-term norm / current-term norm: about 0.70
applied-step norm / current merged-update norm: about 2.23
cosine(applied step, current merged update): about 0.80
```

The outer step is therefore strongly influenced by historical trajectory
memory and is rotated away from the current merged learner evidence. This is a
plausible cause of the late-stage loss increase seen in the common-step
trajectories.

The first policy tested is deliberately simple:

```text
baseline:
  outer momentum = 0.9
  outer LR = 0.175

damped-memory policy:
  outer momentum = 0.5
  outer LR = 0.221667
```

The candidate LR approximately matches the baseline's first-step Nesterov
gain:

```text
0.175 * (1 + 0.9) / (1 + 0.5) = 0.221667
```

This policy retains every candidate, adds no communication or probe overhead,
and does not use oracle labels.

## Controlled Protocol

All runs use the exact-step mode added in commit `7ae4281`:

```text
strict configured quorum = 4
no partial timeout commits
no disconnect-driven quorum reduction
fixed outer-step count
every fragment receives the same number of commits
post-run event-tape validation
```

Shared setup:

| Item | Value |
|---|---|
| Model | `qwen35-9b` |
| Data | `trl-lib/Capybara` |
| Learners | 4, one A100 per learner |
| Fragments | 4 all-RDA `binpack` fragments |
| Local window | 8,192 tokens / 64 optimizer steps |
| Merge | HeLoCo plus RDA |
| Inner LR | 0.001 |
| LoRA rank / alpha | 2 / 4 |
| Pipeline | 2 |
| Delay pattern | 0/800/1600/2400 ms after frozen snapshots |
| External holdouts | two disjoint 256-row Capybara subsets |

All six runs contain exactly 80 contiguous event-tape groups, all groups have

pair therefore passes the predeclared replication gate by a wide margin.

This establishes the joint optimizer setting, not momentum as an isolated
cause. The treatment simultaneously shortens memory and reduces the
constant-direction gain:

```text
baseline DC gain:  0.175 / (1 - 0.9) = 1.750000
treatment DC gain: 0.221667 / (1 - 0.5) = 0.443334
```

The same momentum buffer is also used by HeLoCo before the Nesterov step.
Factorial, DC-gain, and no-HeLoCo controls are therefore required before a
mechanistic claim.

## Decision Gate

Treat damped outer memory as promising only if the full-budget confirmations:

```text
improve both external holdouts on at least 2/3 fresh seeds
have mean gain >= 0.005
have no seed regression > 0.010
agree in sign on internal eval and both holdouts
retain exactly 80 full-quorum groups
add no material systems overhead
```

One positive development seed is not sufficient for a policy claim.

Outcome: `PASS`. The treatment wins the internal split and both external
holdouts on all three untouched full-budget seeds, with mean two-holdout gain
`0.039807` and mean wall-time change `+0.61%`.

## Causal Controls

The following controls were queued before interpreting momentum as causal:

| Control | Arm A | Arm B | Purpose |
|---|---|---|---|
| 2x2 missing corners, seed 137 | `mu=0.9, lr=0.221667` | `mu=0.5, lr=0.175` | Separate the LR main effect from the momentum main effect and their interaction. |
| DC-gain match, seed 181 | `mu=0.9, lr=0.044333` | `mu=0.5, lr=0.221667` | Match `lr/(1-mu)` and test whether shorter memory helps beyond steady-state scalar gain. |
| HeLoCo deconfound, seed 191 | `mu=0.9, lr=0.175` | `mu=0.5, lr=0.221667` | Repeat with `--delta-correction none` so both policies stop feeding different momentum buffers into HeLoCo. |

no-HeLoCo control uses 40 strict full-quorum steps and 350k tokens. No online

### Seed-137 2x2 Factorial

The two missing corners completed 24/24 strict full-quorum groups. Combined
with the original development pair, the complete factorial is:

| Momentum | Outer LR | Internal | Holdout A | Holdout B | Mean holdout |
|---:|---:|---:|---:|---:|---:|
| 0.9 | 0.175000 | 1.3988 | 1.389845 | 1.389379 | 1.389612 |
| 0.9 | 0.221667 | 1.4045 | 1.395155 | 1.395415 | 1.395285 |
| 0.5 | 0.175000 | **1.3918** | **1.380945** | **1.382556** | **1.381751** |
| 0.5 | 0.221667 | 1.3934 | 1.381847 | 1.382909 | 1.382378 |

At fixed LR `0.175`, lowering momentum from `0.9` to `0.5` improves the two
holdouts by `0.008900` and `0.006823`. At fixed LR `0.221667`, the same
momentum change improves them by `0.013308` and `0.012506`. Conversely,
raising LR hurts at both momentum values, by a mean holdout `0.005673` when
`mu=0.9` and `0.000627` when `mu=0.5`.

This short controlled factorial points to a real lower-momentum main effect,
not a higher-LR explanation. It also identifies `(mu=0.5, lr=0.175)` as the
best short-run corner. The effect remains a single-seed, 24-step result and
still shares the HeLoCo momentum buffer, so a full-budget confirmation and
the no-HeLoCo control remain necessary.

### Gain-Normalized Policy Screen

Commit `038f26f` adds two deployable outer optimizers while preserving
Nesterov as the exact default:

```text
normalized-ema:
    m_t = beta * m_{t-1} + (1 - beta) * g_t
    theta <- theta - eta * m_t

restarted-ema:
    if cosine(g_t, m_{t-1}) <= threshold: m_t = g_t
    else: use normalized-ema
```

The first nonzero update initializes `m_t=g_t`, so constant-direction gain is
exactly `eta` from the first commit and is independent of `beta`. This
decouples directional memory from scalar gain. The seed-191 no-HeLoCo queue
therefore includes, on identical data and strict schedules:

```text
Nesterov controls: (mu=0.9, lr=0.175) and (mu=0.5, lr=0.221667)
normalized EMA:    beta=0.9, eta=0.35
outer SGD:         eta=0.35
restarted EMA:     beta=0.9, eta=0.35, restart cosine=0
normalized EMA:    beta=0.5, eta=0.35
```

The `eta=0.35` EMA/SGD/restart arms have identical constant-direction gain,
so their comparison directly tests whether directional smoothing or restart
adds value beyond a stable scalar step. The `beta=0.5` arm was added after
the partial `beta=0.9` mechanism tape showed large history/current ratios and
negative late direction cosine; it is therefore explicitly adaptive
development, not confirmation. These are development screens, not
confirmation results.

### Long-Memory Normalized EMA Failure

The first gain-normalized arm used `beta=0.9`, `eta=0.35`, no HeLoCo, and the
same seed-191 initial state and first-window candidates as the Nesterov arms.
It completed 40/40 strict full-quorum groups, but it is substantially worse:

|---|---:|---:|---:|
| Internal 64-row eval | 1.3515 | **1.3274** | 1.3794 |
| External holdout A | 1.399521 | **1.377213** | 1.427991 |
| External holdout B | 1.402005 | **1.378993** | 1.430937 |
| Mean external holdout | 1.400763 | **1.378103** | 1.429464 |

Online tape diagnostics explain why scalar gain normalization is insufficient:

| Scope | Applied step norm mean | Direction cosine mean | Direction cosine p10 | History/current mean | gnorm / step norm |
|---|---:|---:|---:|---:|---:|
| Full trajectory | 2.3078 | 0.1459 | -0.1412 | 5.1401 | 4.7072 |
| First half | 3.0089 | 0.2135 | -0.1464 | 6.0564 | 3.5775 |
| Second half | 1.6066 | 0.0783 | -0.0880 | 4.2237 | 6.8229 |

Although the policy has unit gain under a constant direction, real fragment
directions change. The long EMA becomes history dominated, often weakly or
negatively aligned with the current merged update, and its realized step norm
collapses late. This is a clean negative result: unit-gain normalization does
not rescue long directional memory by itself.

The remaining equal-gain screens now test outer SGD, conflict-restarted EMA,
and shorter `beta=0.5` normalized EMA. The `beta=0.5` arm was added after
observing these mechanism diagnostics and remains development-only.
