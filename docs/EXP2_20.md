# EXP2.20: Exact Leave-One-Out Action Probe

## Question

Can a production-faithful, current-state action probe identify a harmful
responder inside a complete asynchronous fragment group and improve the final
memoryless Qwen baseline?

This experiment is the first planned online test of an adaptive fragment
commit policy. Earlier ProbeCommit experiments were offline one-step replays;
the only prior online fragment rule was a static fragment-ID learning-rate
profile.

## Baseline

The frozen baseline from EXP2.19 is:

```text
model: Qwen3.5-9B, LoRA rank 2
learners/fragments: 4/4
outer optimizer: plain SGD
outer LR: 0.28
delta correction: none
local window: 8192 tokens / 64 microsteps
delay: 0/800/1600/2400 ms after snapshot
schedule: strict quorum, exactly 80 outer steps
```

## Why The Earlier Probe Is Not Reused

The old direct-action replay did not reproduce the live syncer exactly. It
used flat weighted parameter averaging, while production uses deterministic
per-tensor AVG/RDA and a stateful outer optimizer. It also reused small anchor
splits whose action ranking did not transfer to a disjoint oracle split.

EXP2.20 requires:

1. exact Rust production action previews,
2. validated and learner-ID-sorted candidates before quorum,
3. one in-flight round per fragment,
4. a dedicated anchor set disjoint from training and reported evaluation,
5. paired confidence bounds with token-weighted fallback,
6. a shadow comparator that pays the same probe latency.

## Frozen V1 Actions

For one complete four-responder group:

```text
A0: exact production token-weighted per-tensor RDA over all responders
A1: exact RDA after leaving out responder 0
A2: exact RDA after leaving out responder 1
A3: exact RDA after leaving out responder 2
A4: exact RDA after leaving out responder 3
```

Every leave-one-out action is norm-matched to A0. It is ineligible when its
selected token mass is below `0.70`, its norm multiplier is outside
`[0.5, 2.0]`, or its applied step norm differs from A0 by more than `1%`.

## Selection Rule

The anchor contains eight independent panels, each with two 128-token blocks.
For action `Ai`, define paired panel gain:

```text
d_j = loss(A0, panel_j) - loss(Ai, panel_j)
```

An alternative may replace A0 only when:

```text
mean(d) - 2.365 * SE(d) > 0
mean(d) >= 0.00025
at least 6/8 panels have d > 0
all mass and norm checks pass
```

Any timeout, malformed response, stale preview, NaN/Inf, OOM, or insufficient
evidence falls back to A0. V1 never skips a commit.

## Data Separation

```text
training source window: first 5,064 Capybara rows before deterministic shuffle
anchor: 256 unique rows beginning at source offset 11,000
evaluation E: 512 unique rows beginning at offset 12,000
evaluation F: 512 unique rows beginning at offset 13,000
```

All three generated manifests report zero canonical overlap with the earlier
holdouts and with one another. The evaluation files are unavailable to the
online selector.

## Offline Gate

First replay exact leave-one-out previews over the final seed-223 and seed-239
SGD captures. Seed 223 is development; seed 239 is untouched confirmation.

Proceed online only if:

```text
production baseline next-state relative error < 1e-4
both seeds have positive held-out gain
mean held-out gain >= 0.0005
negative-merge relative drop >= 0.20
strict-negative relative drop >= 0.20
action rate is between 0.05 and 0.50
random leave-one-out does not explain the gain
```

## Online Stages

```text
S0: Qwen3.5-4B, 16 steps, shadow mode, preview/parity/fallback validation
S1: Qwen3.5-9B, 24 steps, active versus shadow, one development seed
C1: Qwen3.5-9B, 80 steps, frozen active versus shadow, fresh seed
C2: repeat C1 on a second fresh seed
```

Shadow mode evaluates A0-A4 but always commits A0. It is the primary
comparator because it matches the active policy's probe delay and cadence.

The confirmation gate is:

```text
both fresh seeds improve on evaluation E and F
two-seed mean loss gain >= 0.003
no reported endpoint regresses
action rate remains between 0.05 and 0.50
probe p95 latency < 30% of one local window
all runs contain exactly 80 full-quorum groups and 20 commits per fragment
```

## Status

The LOO policy is a **no-go**. No active online LOO run was started.

### Final-SGD Buffered Screen

The production replay was first corrected to honor the captured
`delta_correction=none` setting. With that correction, the token-weighted
replay matches the captured next state with maximum step-relative error about
`2.7e-7`.

The older buffered/robust policies do not recover a stable improvement on the
memoryless trajectory. The strongest mean result was
`buffer_group_transport25_normmatch`:

```text
seed 223 gain: +0.0006239
seed 239 gain: +0.0000543
two-seed mean: +0.0003391
```

Its negative and strict-negative safety metrics regress, and the other
buffered, median, consensus, and current-group robust rules are neutral or
negative. A static `1.12x` outer-step multiplier is positive on both seeds but
is optimizer scale tuning, not an adaptive commit policy.

### Eight-Panel Exact LOO Result

The first complete run processed 80 groups per seed with eight anchor panels,
two packed blocks per panel, and a disjoint eight-panel oracle evaluation.

| Metric | Seed 223 | Seed 239 | Aggregate |
|---|---:|---:|---:|
| Groups | 80 | 80 | 160 |
| Action rate | 0.0625 | 0.1125 | 0.0875 |
| Mean gain vs full-group update | +0.0000132 | -0.0000227 | -0.0000048 |
| Negative-rate relative drop | 0.000 | -0.037 | -0.020 |
| Strict-negative relative drop | 0.000 | -0.167 | -0.062 |
| Mean oracle LOO headroom | 0.000820 | 0.000927 | 0.000873 |

The oracle headroom is real, but the anchor-selected action does not recover
it. The confirmation seed is negative and both safety metrics regress.

### Thirty-Two-Panel Follow-Up

Increasing the anchor allocation from eight to 32 panels did not rescue LOO.
Across the same 160 groups, the frozen confidence rule selected no alternative
at all:

```text
action rate: 0
gain:        0
```

Relaxing only the win-rate condition after the run yields gains on the order
of `1e-5` to `5e-5`, far below the predeclared `0.0005` gate. More panel data
therefore reduces false actions but does not make LOO useful enough to deploy.

### Replay Audit

An independent audit found that the first GPU artifacts lacked durable shard
completion metadata, enforceable anchor/oracle manifests, and an aggregate
gate implementation. It also found fail-open handling for non-finite panel
values. Those issues are fixed in the v2 replay and aggregation scripts:

```text
scripts/replay_exact_loo_probe.py
scripts/aggregate_exact_loo_probe.py
tests/test_exact_loo_probe.py
```

The pre-fix artifacts are deliberately rejected by the v2 aggregator. No
non-finite losses, duplicate responders, or incomplete groups were observed in
the completed GPU run, and the result misses the gate by orders of magnitude;
rerunning the same failed LOO policy would not change the no-go decision.

### Decision

Do not deploy `probe_loo_v1`. The next experiment changes the action family,
not the threshold: directly probe a small scalar outer-step grid while keeping
the full candidate group. That experiment is documented in `docs/EXP2_21.md`.
