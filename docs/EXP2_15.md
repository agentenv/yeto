# EXP2.15: Qwen3.5-9B Dense Offline Stress

## Question

Is the action-selection failure just a tiny-model artifact, or does it persist on a harder 9B model with denser m4 captures?

This run used a manual AWS `p4de.24xlarge` instance, not Sky. The instance was terminated after the artifacts were pulled back locally.

## Setup

Model and data:

```text

data: trl-lib/Capybara
settings: m4
learners: 4
fragments: 4
fixed window: 8192 tokens / 64 microsteps
delay pattern: 0,800,1600,2400 ms
delay jitter: 50 ms
LoRA: r=2, alpha=4
seq len: 128
```

Runs:

```text
experiment-results/EXP2/scale-qwen35-9b-p4de-m4-dense-seed31/
```

The original training jobs were stopped after enough syncer captures were collected, then the offline replay was run on the captured states. This is a partial-capture offline stress run, not an end-to-end online training result.

Interpretation:

```text
anchor-vs-oracle action ranking is still too weak for action selection.
```

The 9B run does show some improvement over SmolLM2 in selected mass and strict-negative behavior, but it still does not select utility-improving actions. The deployable oracle has meaningful headroom, so the action space is not empty. The blocker remains measurement/action selection.

## Decision

Do not go online.

This harder-model run rules out the simplest tiny-model explanation:

```text
the phenomenon and oracle action headroom persist on 9B;
the deployable action selector still fails.
```

The best current interpretation is:

```text
candidate-level anchor-gradient signal can exist,
but group-level action ranking remains unstable under disjoint evaluation.
```

## Next

The next experiment should not be a larger online run. It should focus on improving the measurement used for action selection:

```text
1. repeated anchor splits on the same captured groups,
2. lower-confidence-bound action scoring from split variance,
3. action selection only when multiple anchor splits agree,
4. otherwise default to token_weighted or mild shrink.
```

If repeated anchors still do not improve rank agreement, the project should pivot to a diagnostic/benchmark claim rather than an online policy claim.
