# EXP2.14: Action Rank Agreement

## Question

Do anchor-split action utilities rank deployable merge actions the same way as disjoint oracle-split utilities?

This is a local, read-only diagnostic over the existing EXP2.9 per-group replay records. It directly tests the suspected failure mode behind the failed action-probe and conservative policies.

## Inputs

```text
experiment-results/EXP2/probecommit-offline/exp2_9_action_probe/seed53/action_probe_replay.jsonl
experiment-results/EXP2/probecommit-offline/exp2_9_action_probe/seed67/action_probe_replay.jsonl
experiment-results/EXP2/probecommit-offline/exp2_9_action_probe/seed79/action_probe_replay.jsonl
```

Deployable actions:

```text
token_weighted
freshness_weighted
anchor_drop_bottom25
anchor_positive_threshold
anchor_shrink
probecommit_v1
```

Outputs:

```text
scripts/analyze_action_rank_agreement.py
experiment-results/EXP2/probecommit-offline/exp2_14_rank_agreement/action_rank_agreement.json
experiment-results/EXP2/probecommit-offline/exp2_14_rank_agreement/action_rank_agreement.md
```

## Result

Aggregate over 614 groups:

| Metric | Value |
|---|---:|
| Mean Spearman | -0.005 |
| Mean pairwise concordance | 0.497 |
| Anchor top-1 matches oracle top-1 | 0.254 |
| Anchor top-1 gain vs token | -0.000038 |
| Anchor top-1 negative rate | 0.393 |
| Anchor top-1 strict-negative rate | 0.137 |
| Headroom captured | -0.057 |
| Selected mass | 0.534 |

Per seed:

| Seed | Spearman | Pairwise | Top-1 match | Top-1 gain | Headroom |
|---:|---:|---:|---:|---:|---:|
| 53 | -0.040 | 0.482 | 0.256 | -0.000152 | 0.111 |

| 79 | 0.037 | 0.515 | 0.246 | 0.000041 | 0.233 |

## Interpretation

This confirms the failure mode directly:

```text
anchor action ranking is effectively random relative to disjoint oracle action ranking.
```

Pairwise concordance is `0.497`, almost exactly chance. Mean Spearman is near zero. The anchor top-1 action matches the oracle top-1 only `25.4%` of the time despite choosing among six actions, and its mean utility is slightly worse than token-weighted.

Margin filtering does not obviously rescue the signal. Very large anchor margins are rare:

| Anchor margin bin | Records | Pairwise | Top-1 match | Top-1 gain |
|---|---:|---:|---:|---:|
| <= 0.00025 | 166 | 0.521 | 0.301 | 0.000289 |
| 0.00025-0.0005 | 106 | 0.462 | 0.226 | -0.000360 |
| 0.0005-0.001 | 185 | 0.510 | 0.243 | 0.000144 |
| 0.001-0.002 | 101 | 0.485 | 0.257 | -0.000281 |
| 0.002-0.005 | 51 | 0.463 | 0.157 | -0.000723 |
| > 0.005 | 5 | 0.603 | 0.600 | 0.001028 |

The only bin that looks strong is `> 0.005`, but it has only five records. That is not enough to support a deployable policy.

## Decision

Do not continue tuning policies on the existing SmolLM2 EXP2.9 action-probe records.

This diagnostic explains why EXP2.9 and EXP2.13 failed:

```text
the anchor split is not ranking actions in the same order as the oracle split.
```

The next useful work must collect harder and denser scale measurements with either more anchor batches, repeated anchor splits, or both.
